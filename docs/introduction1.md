**第一章 概述与核心哲学**

---

### 1.1 满月平台是什么

满月平台（Full Moon Platform）是一套适用于 JavaScript / TypeScript 的**抽象层、开发规范与相关开发工具链的集合**。

它不是一个传统的运行时框架，也不是某个具体的插件加载器或游戏引擎 SDK。它的核心目标是：

> 让开发者编写**同一套 TypeScript 源码**，通过编译期处理，生成可在多种 Minecraft 服务端插件加载器上运行的插件产物。

目前明确支持或计划支持的目标平台包括：LiteLoaderBDS / LLSE、LeviLamina、BDSX、PNX-JS、LLSE-Lib 等。理论上，只要目标环境有潜力支持JavaScript，满月平台都有可能通过适配器将其纳入支持范围。

满月平台解决的核心痛点是：不同插件加载器之间插件不通用。服主更换服务端时往往需要寻找功能相似的替代插件；开发者则需要为每个加载器重复维护代码。满月平台试图通过统一的开发体验与编译期适配，让“一次编写，多平台运行”成为可能。

### 1.2 核心设计哲学

#### 1.2.1 概念先行，而非实现先行

整个生态的演进顺序是**自上而下**的：

1. 先有 **满月平台** —— 定义“什么是满月插件”的抽象概念、入口规范与构建规则。
2. 再有 **fmplib** —— 把抽象概念具体化为开发者编写插件时必须遵循的 API 契约。
3. 最后有 **LNSDK**（及其他第三方库）—— 遵循前两者的规定，把抽象世界连接到真实存在的服务端加载器。

注意，这与常见的“底层 SDK 驱动上层框架”的思路完全相反。满月平台首先确立“能跨平台的插件应该长什么样”，再通过契约约束开发方式，最后才由适配器负责落地到具体平台。

#### 1.2.2 编译期替换（“偷梁换柱”）

开发时，插件代码依赖的是**空壳参考库**（通常位于项目的 `lib` 目录，内容来自 fmplib）。这个库主要提供：

- 完整的 TypeScript 类型定义
- 详细的注释与文档链接
- 极少量仅供构建工具使用的参考实现

它几乎不包含真实的运行时逻辑。

构建时，`fullmoonplatform` 提供的 `build.ts` 会在临时目录中完成一次关键的“偷梁换柱”操作：

- 根据配置的优先级，将第三方库（如 LNSDK）中对应平台的真实实现，物理复制到临时环境中 `lib` 的位置；
- 然后调用 `tsc` 进行编译。

结果是：源码中的 `import { Player } from "../lib/index.js"` 在编译后实际链接的是针对具体平台的实现代码。最终产物是干净、针对该平台优化的 JavaScript，运行时几乎没有额外的抽象层开销。

这种设计刻意避开了运行时多态（动态 require / 代理等）带来的性能损耗与环境兼容问题，因为不同加载器的 JavaScript 运行环境差异极大。

#### 1.2.3 去中心化与契约优先

满月平台**不强制**使用 fmplib 或 LNSDK。

- 开发者可以自行编写契约层，只要最终产物能正确运行即可。
- 第三方库只要保证：当插件调用契约定义的接口时，在真实服务端上产生正确行为，即可成为合法的适配器。平台不约束第三方库内部如何实现（纯 JS 转换、自建脚本引擎、调用原生模块等）。

fmplib 仅作为**参考契约**和**最大 API 边界**的定义。它规定了“满月平台认可的接口范围”，但并非唯一合法的实现路径。

#### 1.2.4 最大公约数 + 可选特性

- **标准 API**：只收录主流平台都具备类似行为的接口。这些接口保证插件的基础功能可以跨平台运行。
- **可选特性（Features）**：部分平台才拥有的能力。插件在 `plugin.json` 中显式声明需要使用的特性；构建时会裁剪未声明的特性（将其导出设为 `undefined`），以便在不支持的平台上使得插件有能力回退至备选方案，而不会报错崩溃甚至无法通过编译。

使用可选特性会降低兼容性，这是开发者主动选择的结果，平台不会强制禁止。

### 1.3 三大核心仓库定位概览

| 仓库 | 角色 | 主要职责 | 是否必选 |
|------|------|----------|----------|
| **fullmoonplatform** | 概念定义者 + 工具提供者 | 定义插件入口规范、目录规范、构建流程；提供 `build.ts`、`generate.ts` 等工具 | 是（构建工具必需） |
| **fmplib** | 参考契约 | 提供纯 TypeScript 接口定义与文档；作为开发时的类型提示与最大 API 边界 | 推荐（可自写契约） |
| **LNSDK** | 先锋连接器 / 参考实现 | 作为 fmplib 的结构超集，提供多平台真实实现；目前最完整、最全面的适配器 | 非必选（但当前最推荐） |

后续章节将详细展开每个组件的边界、文件结构要求以及它们如何协作。

### 1.4 本章小结

满月平台的本质可以概括为：

- 用**抽象概念**定义“好的插件长什么样”；
- 用**契约库**规定开发者如何写代码；
- 用**编译期物理替换**把契约变成针对具体平台的实现；
- 用**去中心化**的方式允许社区编写自己的适配器。

它追求的不是“再做一个新的加载器”，而是“让现有的、未来的各种加载器都能用同一套 TypeScript 插件源码”。

理解了这一章的核心哲学后，再阅读后续的架构与构建系统章节，会更容易抓住设计意图，而不是被具体实现细节带偏。
